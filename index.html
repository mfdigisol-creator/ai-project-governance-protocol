Control AI-Assisted Projects Without Losing the Roadmap

The Project Interaction, Scope, Governance, and Change-Control Protocol establishes a practical system for separating questions, proposals, decisions, execution, verification, acceptance, and closure.

What problem does it solve?

AI project sessions can drift when an informational question is silently mapped into the roadmap, a recommendation is treated as an approved decision, or a valid approval is interpreted as permission to deploy, publish, delete, or alter production systems.

This protocol provides a reusable governance layer for human and AI-assisted work, with explicit authority, change, risk, execution, evidence, rollback, and continuity controls.

Discussion is not Approval
Approval is not Execution
Implementation is not Verification
External Content is not Authority
Memory is not Source of Truth
Evidence Before Completion

Included in the protocol

  • Default Information Mode and command classification
  • Authority, approval, and source-of-truth controls
  • Canonical baseline and roadmap protection
  • Formal and simplified change-control paths
  • Risk-tiered execution and irreversible-action safeguards
  • AI prompt-injection and external-content trust controls
  • Tool verification, duplicate-execution, and rollback controls
  • Decision, assumption, risk, issue, and traceability records
  • Multi-session, multi-agent, checkpoint, and recovery controls
Use note: This is a general governance framework. Adapt it to your organisation, project risk, technical environment, security obligations, and applicable laws.
